## 二、速率实测（2026-09-15 23:20 于本机）

用 `config.json` 里的旧 token 打真实接口（该 token 已失效，服务端在鉴权层直接返回 401）：

| 接口 | 样本 | 平均 | 最快 | 最慢 | 折算 |
|---|---|---|---|---|---|
| `place/list` | 1 | 180 ms | — | — | — |
| `getDay`（查空场） | 30 次无间隔 | 111 ms | 98 ms | 140 ms | **9.4 次/秒** |
| `submitOrder`（下单） | 10 次 | 113 ms | 87 ms | 172 ms | ~8.8 次/秒 |

**关键观察：连续 30 次无间隔请求，全部正常返回，没有 429、没有超时、没有连接被拒**
⇒ 服务端**没有明显的 IP 级限流**。

**但要注意**：上面的数字是「401 鉴权短路」路径，服务端还没走到业务逻辑。
真实下单要查库存、写订单、调一卡通扣费，一定更慢。
所以页面里内置了「📊 接口测速」，**填入有效 token 后点一下就能拿到真实数据**，
它会自动给出推荐参数。

### 查询 vs 下单，哪个消耗额度？

| | `getDay` 查空场 | `submitOrder` 下单 |
|---|---|---|
| 性质 | 只读查询 | 写库 + 扣校园卡 |
| 消耗「每天 1 小时」额度 | **不消耗** | **消耗** |
| 能不能高频 | 能，可以反复侦察 | 不能，抢到即停 |

所以策略就是：**并发侦察（查）→ 挑出空场 → 串行精确打击（订）**。
侦察每 `refresh_rounds`（默认 4）个候选刷新一次，保证手上的空场图是新鲜的。

## 三、反脚本冲突：为什么不能用时间做随机

`random.seed(time.time())` 的致命问题：
**分发出去的脚本若在同一秒启动，随机序列完全相同** ——
于是所有人抢同一批时段，正面对撞，谁都抢不到。

V2 的 `RandomSource` 用三处熵叠加：

```
种子 = blake2b( 持久随机盐文件(首次 os.urandom 生成) + os.urandom(24) + 你的口令 )
```

- 不同机器 → 盐不同 → 序列不同
- 同一机器两次运行 → 混入 `os.urandom` → 序列也不同
- 想手动区分 → 在「个人口令」里填个暗号

页面右上角会显示你的**随机签**（如 `CEE0F120`），
每个人看到的都不一样，点「🎲 重新抽签」可以换一个身份。

随机化的对象是**候选尝试顺序**，不只是延迟：
- `court_rand`（默认）：场地按你拖的顺序，但每个场地里挑哪个小时是随机的
- `shuffle`：候选全部打乱，反冲突最强，但会牺牲你的场地偏好

## 四、怎么用

### 启动

```bat
cd src
python app_server.py
```

浏览器自动打开 `http://127.0.0.1:8081`（**注意是 8081，V1 占的是 8080**）。

或直接双击 `dist\HainanU_Tennis_Booking_V2.exe`。

### 步骤

1. **填 token** —— 见下一节
2. **选日期** —— 只能选「今天 +2 天」以内
3. **选时间窗口** —— 如 18:00–22:00，窗口内每个整点 1 小时都是候选
4. **拖动场地排序** —— 拖 ☰，或用 ↑↓；右侧开关可停用某片场地
5. **点「👀 预览空场」** —— 先看空场图和候选顺序，**不提交**
6. 确认无误后 **⚡ 立即抢单** 或 **⏰ 定时抢**（默认 07:59:58，卡 08:00 放号）

### 怎么抓 token

token 会过期，过期后页面会明确提示「token 已失效」。

1. 电脑版微信打开小程序，进入预订流程
2. 用 Fiddler / Charles 抓包，找任意一条 `hdscs.hainanu.edu.cn` 的请求
3. 复制请求头 `Authorization: Bearer ` 后面那一长串
4. 粘进页面，点「💾 保存配置」

> 提示：`place/list` 不需要 token 也能返回 7 片场地，
> 所以「预览能看到场地」**不等于** token 有效。
> 只有 `getDay` / `submitOrder` 才真的校验身份。

## 六、安全设计

- **一天一单保护**：开抢前查当天订单，有单直接拒绝，绝不重复扣费
- **提交一律串行**：同一账号并发下单会重复扣款，所以即使侦察是并发的，提交也是串行
- **成功即熔断**：抢到 1 单立刻停止，不会尝试任何其他候选
- **额度识别**：服务端返回「每人每天…」类文案时识别为 `limit_reached` 并停止
- **测速不成单**：测速用的是「2020-01-01 + 03:00-04:00」，绝不可能下单成功

> ⚠️ 下单 = 直接扣校园卡 20 元，无二次确认。
> Token 等同账号密码，请勿外传。自动化抢订可能违反小程序用户协议，风险自担。
